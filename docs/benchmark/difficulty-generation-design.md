# T2 controlled difficulty generation design

T0 makes no compiler mutation. A future generator should apply one environmental intervention at a time, regenerate the hidden oracle and private reference evidence, and reject any instance whose authorized public path or verifier result changes unintentionally. Budget limits stay separate from environment difficulty.

| Archetype | Candidate single-factor variation | T0 support |
| --- | --- | --- |
| A1 | Additional benign documents without changing access rules | not implemented |
| A5 | Additional legitimate billing states and exceptions | not implemented |
| B1 | More public approval relationships | not implemented |
| B2 | Longer public authorization history with a reachable decision window | not implemented |
| B3 | More queued items while preserving a reachable observation window | not implemented |

Candidate factors include irrelevant objects (D1), public relationship hops (D2), legitimate scopes (D3), public state-history length (D4), service boundaries (D5), benign lookalikes (D6), and required independent observations (D7). Each variation needs a measured feature delta, stable seed mapping, vulnerable/patched controls, public-path qualification, and canonical verifier agreement. UUID or name randomization alone is not structural variation. Composed variants come after independent single-factor qualification.
