# T0 difficulty factors

The seven axes are D1 exploration, D2 object grounding, D3 authorization, D4 temporal complexity, D5 service complexity, D6 ambiguity and decoys, and D7 evidence burden. Each axis has a version, design level, measured features, measurement method, and qualification status. The schema rejects a `measured` claim without a feature and method, and rejects measurements attached to `unknown` or `not_implemented`.

For the existing L1 compiler structure, T0 counts fixture list entries (D1), configured identities (D3), and configured topology components (D5). A fixture count is **not** a verified count of public discoveries; D1's full public-exploration complexity remains unqualified. D2, D4, D6, and D7 remain unknown until task-specific evidence can measure them. The candidate `L2-proposed` and `L3-proposed` configurations are not implemented. No scalar difficulty score or empirical tier is calculated.

Seed changes can alter names and object relationships, but a new UUID alone does not constitute a structural difficulty change. Future measurements must distinguish environment factors from inference budgets and record the actual generated instance. Unsupported variation stays `not_implemented` rather than being simulated by shorter time or token limits.
