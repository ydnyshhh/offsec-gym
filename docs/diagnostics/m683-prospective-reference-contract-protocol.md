# M6.8.3 prospective reference-contract protocol — review draft

**Status:** study design only. No live treatment, manifest, model call, approval, or collection is authorized by this document. The detached replay and PostgreSQL qualification cannot establish model uptake or effect. A separately reviewed runtime implementation, model-facing exposure audit, complete parameter pins, and independent execution authorization would be required before any future study.

## Question and contrasts

The feasibility question is whether broader, unambiguous reference acceptance increases **authoritative experiment-state activation** without changing task information. Three prespecified arms would differ only in backend reference-contract acceptance: C0 direct `StartExperimentArgs`, C1 frozen canonical typed grammar, and C2 C1 plus the experiment-defined `change:` alias. A proposal is accepted only when **every** target reference and every other existing schema field validates. No target may be dropped, inferred, substituted, or selected using hidden fixtures.

The primary proposed design is **A: byte-identical model-visible tool definitions** in all arms, with backend acceptance as the sole assigned contrast. This more closely isolates validation semantics, but may limit uptake because the model is not told that typed forms are accepted. Before proceeding, an independent reviewer must verify byte-identical initial tool schema, names, descriptions, prompts, and error-format rules. The *realized* tool responses and later model histories may diverge after a contract accepts or rejects a proposal. Such feedback is a treatment consequence, not by itself an exposure violation. Record the first proposal and its response separately from later proposals, responses, and state use. Treat later feedback as a possible mediator; do not require identical realized feedback histories or condition the all-assigned endpoint on them. If identical **initial** exposure cannot be achieved, **B: arm-specific model-visible language descriptions** is a different experiment, requiring its own protocol and interpretation. A and B must never be mixed within this study.

## Exploratory sample and assignment plan

The proposed feasibility cohort is **16 fresh matched blocks × 3 contracts = 48 assigned cells**. Four blocks occur in each stratum: B2-S3 vulnerable, B2-S3 patched, B3-S2 vulnerable, and B3-S2 patched. This is not a powered confirmatory sample. Generate new eligible seeds with a cryptographic random generator, reject any historical evaluation seed, freeze the ordered seed list and its digest before assignment, and retain the exact list privately. Within each block, assign one cell to each contract; prespecify a balanced permutation schedule so each arm appears in each execution position as evenly as 16 blocks permit. Freeze the block-to-cell mapping and order before any outcome is observed.

### Proposal-uptake feasibility gate

Only **12 of 114** historically trace-auditable cells emitted an experiment proposal. If that observed fraction carried over unchanged, 48 assigned cells would yield about **5 proposal-producing cells total**, or **1–2 per arm** on average. This is a planning scenario, not a transportable rate estimate: the historical cells differ from a fresh prospective cohort, and proposals within matched blocks need not be independent. The 48-cell study can still estimate all-assigned activation descriptively, but this scenario supplies little information about conditional contract acceptance.

Before any prospective execution, freeze a proposal-frequency justification by stratum and arm, an expected number of **auditable proposal-producing cells** per arm, and a precision rationale for the intended conditional comparison. A minimal screen for even a coarse conditional acceptance estimate is a defensible projection of **at least 12 auditable cells with a first proposal in each arm**. At 12 independent cells, a 95% Wilson interval around 50% acceptance has a half-width of about 0.25; dependence or missingness can make precision worse. This is a precision screen, not power for an arm difference. If the projection is unsupported, redesign the cohort or explicitly restrict the 48-cell study to uptake and observability feasibility, with no planned C0/C1/C2 acceptance comparison. After collection, below 12 proposal-producing cells in any arm, report conditional acceptance counts and denominators with uncertainty, without an arm ranking. Even above that floor, conditional comparisons remain descriptive and cannot establish a causal or confirmatory ordering. Never add, replace, or selectively continue cells in response to observed uptake without a separately reviewed design.

Each assigned cell needs an independent model history and environment instance. The same pinned model revision, provider route, prompts, non-reference tool definitions, task information, token ceilings, model-call ceiling, HTTP ceiling, worker clock, and other execution limits must apply across arms. No exploration guidance, hypothesis suggestion, grounding hint, correct identifier, automatic plan, extra turn, extra HTTP budget, or evidence reminder may differ. The provider/model revision, rates, exact per-cell ceilings, cumulative ceiling, and stop thresholds are **unfilled execution parameters** requiring separate verification and review; this draft cannot be used as a run manifest. Historical M6.7.1 pricing and approval receipts are not execution authority for this study.

## Endpoints and evidence

The primary endpoint is `experiment_state_created`, proven only by an authoritative persisted `ExperimentStateChanged` start event attributed to the assigned run. The denominator is **all 48 assigned cells**. A completed auditable run without a proposal is non-uptake and activation false. Provider failure, environment failure, or unauditable primary evidence is unknown; it is not imputed as false.

Secondary endpoints should be reported as a causal chain rather than collapsed into one success score: proposal emitted; valid JSON arguments; assigned-contract syntax accepted; unchanged schema accepted; controller rejection; state created; independently public-source grounded; correctly typed public entity; state retrieved; state updated; state marked completed; relevant action attempted and completed; required observation collected; verified target transition; finding submitted; finding validated. Report **first-proposal acceptance conditional on an auditable first proposal** separately from the all-assigned activation endpoint, using proposal-producing cells as the denominator. Also report proposal frequency per assigned cell and, as diagnostics, acceptance of later proposals with cells clustered rather than treating repeated proposals as independent units. Conditional acceptance is a descriptive, post-assignment process measure: earlier treatment-induced feedback can change whether a later proposal occurs or what it contains, so it does not identify an arm effect on its own. Existing experiment-state events can establish creation, update, and completion. Tool-call and model-response traces may establish proposal, JSON, rejection, and retrieval only after a separate source audit confirms capture and attribution. Public grounding requires the M6.8.2 delivery and typed-record standard. Action, observation, transition, and finding endpoints require separately audited trace or verifier sources. A detached synthetic test establishes none of the later model-behavior endpoints.

## Missingness and analysis

Report C1−C0, C2−C0, and C2−C1 as exploratory matched comparisons. For each arm, report observed activations, non-uptake, observed failures, unknown outcomes, and the all-assigned activation interval `[observed activations / 16, (observed activations + unknown) / 16]`. For each pair, report complete-block descriptive differences and the number of incomplete blocks; do not silently discard or impute unknown cells. Stratify proposal rates, publicly grounded activations, later-use rates, token usage, and execution overhead. Keep B2 and B3 security-task outcomes separate. No confirmatory p-value or security-success uplift is justified by this 48-cell feasibility design. A later confirmatory study would require its own power calculation, frozen analysis, and multiplicity plan for all three contrasts.

Stop criteria must be frozen before execution and include: unexpected contract drift; unequal model-facing exposure; source-integrity failure; budget or retained-reservation uncertainty; provider or environment failures that make primary outcomes unauditable; repeated data loss; or a safety/integrity concern. Never retry or replace a started cell without a separately reviewed protocol. The cost worksheet must use current pinned input and output rates and calculate upper-bound spend from per-cell token ceilings, model-call limits, unknown-cost failures, retained reservations, and a cumulative stop. No provider preflight or credential use is part of this PR.

## Separate hypothesis-identifiability question

M6.8.2 verified public foreign-key relationships among proposed objects in ten proposals, but none of the 18 free-text hypotheses had a structured, independently checkable predicate-to-relationship contract. A future study could ask whether model-authored fields such as `entity_kind`, `relationship`, `related_entity_kind`, and `expected_observation_type` make hypotheses testable. That study would require its own public-evidence validator and must not derive predicates from hidden target anchors. It is **not** part of C2 or the three-arm reference-contract comparison.

## Go/no-go before any prospective execution

The current status is **no-go for live treatment**. Required independent work includes a reviewed runtime implementation; proof of Design A initial-exposure equivalence or a new Design B protocol; the proposal-uptake justification and reporting gate above; frozen alias grammar and analysis; new nonoverlapping seeds and assignment; exact model, provider, budget, health, missingness, and stop pins; demonstrated primary-event observability; and a new human-approved execution scope. The historical alias was selected after seeing the cohort, so the present replay is exploratory retrospective qualification only.
