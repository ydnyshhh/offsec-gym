# M6.7 stage-specific interventions — engineering design

**Status:** design and no-model qualification only; unapproved and unrun as a live study. No sample, seeds, paid manifest, or effect estimate are frozen here.

## Prior evidence and question

M6.6 found 38/60 complete trusted Range A witnesses with the witness package versus 7/60 control, while the control arm caused the target refund slightly more often. M6.6.1's excluded feasibility cohort finished 96 assignments with 92 completed source cells and 48 pair receipts. Its two B2-S3 vulnerable transitions did not become complete trusted witnesses or validated roots. B3 frequently lacked a decisive target cancellation and follow-through. Its reporting attempts often failed schema or same-run reference checks, and adjacent exact model outputs recurred despite distinct request hashes. These are descriptive observations, not proof of the cause of stagnation or an estimate of a new treatment effect. The frozen results and traces remain unchanged.

M6.7 asks which *separate* intervention repairs which edge: reporting (`evidence → provenance → valid report`) or experiment commitment (`hypothesis → committed test → causal action → transition`). It does not create a combined “better agent.” The model still decides the security meaning and the experiment.

## Existing trust boundary

`MonolithicSecurityAgent` constructs tools in `model_tools`, dispatches gateway and finding calls, and creates each provider request in the run loop. The gateway writes redacted `RequestArtifact` and `Evidence` files, linked by `ActionRequested` and `ActionCompleted` events. `ModelCallArtifacts` stores exact request/response payloads and hashes. `EventWorldState` holds factual observations; `EventWitnessLedger` projects temporal proof. The deterministic validator subsequently loads the private oracle, build fixture, and hidden root mappings. Neither M6.7 model-visible tool may import or invoke that validator, oracle store, ground-truth manifest, or fixture. This is the primary leakage risk.

The catalog must filter by **current run, instance/generation, model-originated action, completed action, current task/worker, and pre-terminal sequence**. Trusted bootstrap or checkpoint actions, other runs, and private setup traces are excluded even when their facts appear in WorldState. It reads the already redacted request/evidence artifacts and checks their event bindings; it does not create a second evidence database. Bounded response text is optional; no hidden labels or private anchors are read.

The public route shapes in `range_surface`/`enterprise.ROUTES` are the only canonicalization vocabulary. The helper matches literal segments and UUID placeholders deterministically. Ambiguous or malformed paths fail. Route shape is a syntactic fact, not a root hint.

`preflight_finding` parses the selected existing finding tool schema, then checks only current-run citation IDs, action/evidence binding, canonical route spelling, sequence and duplication. It may return deterministic citation fields for a referenced evidence ID. It never calls the finding sink or validator and never evaluates a security property, vulnerability, novelty, target, or reward. It cannot promise that a finding will be accepted. Baseline `submit_finding` behavior stays untouched.

The added model tools are `list_candidate_evidence(identity_id, method, route_shape, sequence_start, sequence_end, status_code)` and `preflight_finding(finding_tool, arguments_json)` for A, plus `start_experiment(hypothesis, subject_identity, target_objects, preconditions, planned_steps, expected_positive_observation, expected_negative_observation, required_evidence)`, `get_active_experiment()`, `update_experiment(experiment_id, current_step, status, blockers)`, `complete_experiment(experiment_id)`, and `abandon_experiment(experiment_id, reason)` for B. Their exact provider-facing JSON schemas and hashes are recorded in the qualification artifact. Catalog output is capped at 20 entries and the shared retrieval carry budget (2,000 characters by default when called directly); response excerpts are capped at 320 characters. The preflight tool returns reason codes and bounded, mechanical citation facts only. It does not auto-submit or rewrite a security claim.

The preflight interface keeps its generic `finding_tool` and `arguments_json` request schema, preserving A-arm tool schemas. On a successful, bounded response it now echoes the parsed JSON object as `canonical_arguments`. The echo is the exact input object: it does not rewrite claim, security expectation, observed/expected behavior, or root hypothesis. If the response would exceed the carry limit, the object is omitted with `canonical_arguments_omitted_reason=output_limit`. Failed preflight never returns it. This reduces a second JSON-string serialization step while leaving final submission a separate model decision. It does not guarantee the model will submit or that a finding is correct.

## Independent switches and storage

Two default-false flags, `provenance_reporting` (A) and `experiment_commitment` (B), independently add tools. The explicit arms are A0B0, A1B0, A0B1, and A1B1. Tool schema hashes are pinned in a no-model qualification artifact. The base prompt, model, budget, gateway, validator, visibility, and range routes do not change. A concise active-experiment reminder is the only extra context in B arms. A arms add tools only. No tool or reminder leaks into baseline.

The opt-in M6.7 runner binds the arm flags and tool-schema hash into its `RunStarted.experiment_hash` alongside the unmodified base `ExperimentSpec` hash. Identical base specs in different arms therefore have distinct, reproducible run identities. The historical runner and frozen spec serialization remain unchanged.

`WorldState` remains observations, `WitnessState` remains temporal proof, and `ExperimentState` is an append-only, current-run model-authored hypothesis/plan lifecycle. `ReportingState` is derived from authoritative action/evidence references and preflight events rather than duplicating responses. A second active experiment is rejected until the first is completed or explicitly abandoned. The model can abandon any experiment; no hidden root-specific plan is generated. Reminder text is bounded and contains only model-authored fields and lifecycle status.

`current_step` is the number of planned steps the model declares complete, from zero through the number of planned steps. The mutation rejects a larger number with `experiment_step_out_of_range` and rejects regression. The state and reminder are a scaffold for the model's own plan; they are not mechanically verified task progress.

## Stage metric semantics

The generic offline analyzer keeps independent predicates. `decisive_root_action_attempted` is backed by an externally reviewed set of `ActionRequested` IDs; `decisive_root_action_completed` is backed by `ActionCompleted` IDs; `target_transition`/`transition_reached` require separately supplied transition action IDs. A completed decisive action does not itself establish the target transition. `complete_witness` requires separately supplied completed-action evidence IDs. Model-marked experiment completion, abandonment, blocking, and completed-step count describe only the model-authored scaffold; they do not imply any of these verified stages.

`finding_recorded` counts any `FindingSubmitted`; `root_class_submitted` counts only IDs supplied by a separately reviewed root-specific extractor. `any_finding_after_transition` and `any_validated_finding_after_transition` are descriptive generic events. `root_recorded_finding_after_transition` requires a supplied root-class finding ID recorded after the target transition; `root_validated_finding_after_transition` additionally requires a validated verdict linked by `result.finding_id` to that same later root-class finding. A later unrelated finding, even if validated, does not count as target transition-to-root-report conversion. `root_submission_attempt_after_transition` is always `null` in generic analysis: a malformed or rejected submission cannot be assigned a root class mechanically. The generic `any_submission_attempt_after_transition` may count rejected submit calls, but is not a target conversion metric. No route, finding text, or validator heuristic supplies root identity here.

## Response-stagnation diagnostic

Offline fingerprinting reads verified model-call artifacts. `raw_request_sha256` hashes the exact serialized provider JSON body. `semantic_request_sha256` hashes a canonical object with transport-only metadata removed; no model-visible text, role order, tool order, tool result, or reasoning setting is removed. Component hashes split instructions, input/context, normalized messages, normalized tool results, and tool schemas. Missing artifacts or fields are explicit unknowns, not invented equalities. Adjacent response/reasoning/tool-batch repeats are descriptive; POST-bearing and GET-only repeats are distinguished, with auditable token/cost attribution only when usage exists. The collector never suppresses duplicate actions.

The only stripped request fields are these **top-level transport fields**: `request_id`, `trace_id`, `event_id`, `transport_timestamp`, and `transport_metadata`. All nested content remains. Canonicalization sorts JSON object keys, uses compact separators and UTF-8, and preserves array order. The component called `normalized_message_sha256` hashes the full ordered `input` array; `normalized_tool_result_sha256` hashes its ordered `function_call_output` subset, including model-visible call IDs. `user_context_sha256` hashes ordered user messages. `prior_response_sha256` and adjacent `exact_response_repeat` hash/compare ordered response `output` items after omitting generated output-item `id` and `call_id`; reasoning text and exact function argument strings remain. `exact_tool_batch_repeat` compares the ordered `(tool name, exact argument string)` batch, matching the older adjacent-batch notion. The raw request hash uses `request_wire_bytes`, which excludes HTTP headers. Endpoint and resolved model revision are optional recorded metadata, never guessed.

A later separately approved controlled replay could compare: A exact serialized request; B same semantic payload with regenerated transport ID; C one irrelevant textual perturbation; D deterministic ordering normalization; E shorter context retaining the last decision-relevant state; F an alternate endpoint **only** if a future protocol expressly approves it. Equal outputs under any pair alone would not identify a cause. This PR makes no provider call.

## Future analysis and missingness

Run records retain separate fields for exploration, experiment, transition, witness, reference binding, submission, and validation. Marginal stage flags are not forced into a monotone funnel; temporal claims require checked event order. Intact provider-failed traces retain pre-terminal stages. Corrupt or unreconstructable evidence becomes assigned missingness; unexpected analyzer errors abort analysis. `score_valid` and `trace_auditable` remain distinct. If a started model call lacks auditable completion, `resource_auditable=false` and token totals are `null`, not zero. No complete-case filtering is implicit.

The offline analyzer requires one terminal event at the end of an ordered, single-run trace and verifies referenced request/response and gateway artifacts. A future, separately reviewed root-specific extractor must supply transition, decisive-action, complete-witness and root-class IDs; this generic module does not infer those from route names. Submission citation mismatch and absent same-run references are counted directly from attempted model tool arguments for comparability across all four arms. Preflight reason-code counts are reported separately. Route rejection counts use the existing public route table only when the trace identifies one public range family; otherwise they are `null`. Actions and tokens per experiment are arrays over each experiment's own start-to-completion/abandonment window, or start-to-terminal if still active. These counts measure activity, not hypothesis quality. Token counts are `null` if model usage is unauditable. Validation outcomes are read only offline; they are never returned by the model-visible tools.

## Safety, qualification, and future work

All actions remain inside the synthetic gateway. No arbitrary shell, host filesystem, external network, credential, or public exploit tool is added. The gateway remains the scope enforcer. Qualification uses focused no-model tests plus real Range A and Range B Compose gateway actions, with persisted request/evidence binding, trusted setup exclusion, cross-task/run isolation, public route canonicalization, and same-run preflight. No model provider is called. A real post-terminal gateway action would violate the valid trace contract, so that exclusion is exercised in a focused unit test. The future factorial protocol needs its own frozen sample, endpoint, budget, approval, and read-only postcheck before paid execution.

M6.7A does not teach the security answer. It only reduces provenance and schema bookkeeping failure. M6.7B does not supply a root-specific plan. The model must formulate the hypothesis and experiment. A later PostTrain study could ask whether transition-to-proof-to-report and hypothesis-to-experiment behavior can be internalized; it should deduplicate repeated achievements rather than reward repeated validator success. Training is outside this milestone.
