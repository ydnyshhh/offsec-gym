## Question and design

This is an excluded diagnostic of where Range B behavior begins to recover when a fresh unchanged agent starts from verified environmental checkpoints. It is not a confirmatory treatment estimate and its seeds may not be reused in a later confirmatory study.

Eight fresh numeric seeds are selected deterministically from the frozen M6.6.1 exclusion registry before inspecting their fixtures. Every seed is assigned all six states: B2-S0/S2/S3 and B3-S0/S2/S4. Every state has one vulnerable and one patched, independently built instance. This makes **96 cells** in eight 12-cell seed blocks. The checkpoint order within each seed follows a seed-labeled balanced cyclic Latin schedule; each checkpoint occupies each position at least once. The vulnerable/patched order is balanced four/four for every checkpoint. The full order, IDs, seed list, and assignment hash are recorded in the later immutable manifest. No cell is retried or replaced based on its result.

The broad baseline monolithic policy is unchanged: structured memory, known routes, deterministic validator, full normal budget, and witness planning **off**. Model and reporter behavior are not tuned to checkpoint. The existing Range B config must have identical bytes at the source and protocol commits and is pinned by hash. Trusted checkpoint setup has its separate zero-model budget and private receipt. The agent receives no target label, setup transcript, or answer in memory. S1 remains omitted.

The principal comparable endpoint is **offline full transition** (`full_transition` / `offline_complete_chain`): audited trusted prerequisite state plus audited model actions and resulting state. Checkpoint-relative experiment completion is secondary. Same-run complete witness and frozen validator rates are descriptive at S0 only; the other checkpoints cannot generally supply setup evidence to that validator. Patched finding submissions count all submitted security claims, including those with inconclusive validation; rejected and inconclusive verdicts are reported separately. A missing patched trace has no reconstructed submission count, rather than a count of zero.

The analysis reports all 96 assignments, terminal status, `score_valid`, `trace_auditable`, data-integrity attrition, and best/worst missingness bounds. An intact provider-failed trace can retain preterminal stages even when score-invalid. An unstarted or unreconstructable cell remains assigned with missing stage outcomes. The authoritative postcheck handles only expected receipt/event/artifact integrity failures as per-cell missingness; unexpected stage-extraction or assignment-analysis exceptions **abort the postcheck globally**. Missing resource use is `null` with `resource_auditable=false`, never silently zero. If a model call started but lacks a completion event, the call count remains known while token totals are unknown. Within-seed contrasts and seed-pair bootstrap intervals are descriptive because this feasibility pilot is excluded from confirmatory inference.

## Worker clock and validity gates

Checkpoint states differ both in workflow semantics and in deterministic worker-clock position induced by trusted setup HTTP requests. For B3, `queued_tick`, `due_tick`, and `ticks_since_queue` in the private receipt establish the exact position at first inference. The four-tick window can make S2/S4 behavior operationally difficult. Tables must show this clock position and setup action count next to the response curve.

Before a cell starts, verify its frozen assignment, fixture/build/pair binding, checkpoint module SHA, source and protocol checkouts, private receipt, selected endpoint and price, cumulative estimated token cost, and absence of a prior run/reservation. After a cell, reconcile authoritative PostgreSQL event identities, contiguous sequences, trace hashes, request/evidence artifacts, stage extraction, score status, and resource usage. An isolated transient provider failure is retained without retry after authoritative reconciliation. Pause after two consecutive transport failures or three provider failures in ten started cells. Auth/quota/request errors, endpoint/revision/price drift, integrity or analysis failure, reservation ambiguity, and cost-cap breach stop collection. Any later health-epoch reset or resumed unstarted prefix needs its own reviewed operational amendment and explicit scope-bound approval.
