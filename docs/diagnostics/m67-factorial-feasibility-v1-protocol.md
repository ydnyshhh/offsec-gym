# M6.7 factorial feasibility protocol (prospective)

**Status:** proposed, unapproved, and unrun. This document fixes the design of a bounded four-arm pilot; it is not a live manifest or permission to spend. No sample seeds, fixture contents, paid-call approval, collector, or effect estimate are created in this PR. The qualified intervention source is PR #52's merge commit `f5273e6d59d2810ac7de2646c238a2d0672dc042`. The final protocol commit can be pinned only after this PR merges.

## Question and scope

The two independently switched interventions are A, provenance-grounded reporting, and B, model-authored experiment commitment. The four assignments are A0B0, A1B0, A0B1, and A1B1. The pilot asks whether A changes the evidence-to-recorded-root-report edge, whether B changes the hypothesis-to-decisive-action/transition edge, and whether the combined arm is operationally separable. It does not presume that either intervention affects only its intended edge: all upstream and downstream stages will be reported by arm.

This is a **feasibility pilot**, not a powered confirmatory test. Its arm differences and A-by-B interaction are descriptive. It cannot establish a population treatment effect or validate a post hoc mechanism. A later confirmatory study needs new seeds and its own protocol. The M6.6 and M6.6.1 cohorts are excluded from this pilot's estimates and are not rescored. The separate response-stagnation replay proposed in the [engineering design](m67-stage-interventions-design.md) is outside this pilot; adjacent repeats are measured offline only.

The Range B checkpoint states are intentionally stage-enriched. B2-S3 begins after a trusted role-revocation setup; B3-S2 begins with a queued target job. The setup is identical across arms and invisible to the model as a transcript. S3 and S2 do **not** represent ordinary fresh-start performance. The B3 worker-clock position, due tick, and setup action count must be recorded before first inference and reported beside the stage outcomes. Range A has no added critical checkpoint. Do not pool its rates with the two Range B checkpoint strata as a single effect.

## Seed and order lock

Before looking at any new fixture, construct a versioned exclusion registry from every seed assigned in the frozen M6.4 through M6.6.1 study manifests, including stopped and outcome-missing assignments. Bind that registry and each referenced manifest by SHA-256. The pilot seed selector scans decimal ASCII counters from zero and takes the first eight distinct, nonexcluded values from `100000 + int.from_bytes(SHA256(UTF8("m67-factorial-feasibility-v1|seed|<counter>")).digest()[:8], "big") % 800000`. Seed selection uses labels only; fixture inspection, model outputs, and validator results cannot enter selection.

The manifest must list all 192 rows and their immutable order before any model call. Within each seed block, rotate the fixed stratum order (Range A, B2-S3, B3-S2) by `seed_index % 3`. Rotate the fixed arm order (A0B0, A1B0, A0B1, A1B1) by `seed_index % 4`, so every arm occupies each arm-order position twice across eight seeds. For each seed/stratum/arm, set vulnerable-first when `(seed_index & 1) XOR (SHA256(UTF8("m67-factorial-feasibility-v1|variant|<stratum>|<arm>")).digest()[0] & 1)` is zero; verify four/four balance per stratum/arm. Each cell uses a fresh run, instance, and generation; no fixture or model state carries from another arm. The exact row list, identifiers, fixture/build binding, config bytes, checkpoint receipt, source/tool-schema hashes, seed registry, and assignment SHA belong in a create-once manifest after protocol merge. No cell is retried, replaced, or dropped because of its result.

## Outcomes and comparisons

All stage flags are extracted from authoritative events and artifacts, with separately reviewed root-specific IDs. `ActionRequested`, `ActionCompleted`, verified target transition, complete witness, finding recorded, and validated root remain distinct. A completed decisive action requires the same ID to have a model-originated decisive request classification. A finding after transition counts as a **root** report only when the offline root-specific extractor binds that recorded finding to the target root; a validated-root stage separately requires a later validated verdict linked to that same finding ID. An unrelated finding is not conversion. A model-marked experiment completion is self-reported scaffold state, not verified task progress.

The prespecified all-assigned pilot readouts are:

1. **A edge:** per arm and stratum, the fraction of assigned vulnerable cells with a verified target transition followed by a recorded root-class finding whose cited action/evidence pairs are valid same-run references. A's marginal difference averages A1B0/A1B1 versus A0B0/A0B1 within each stratum. This is an all-assigned composite; it does not condition the treatment contrast on reaching transition.
2. **B edge:** per arm and stratum, fractions of assigned vulnerable cells with a model-originated decisive action request, a completed decisive action, and a verified target transition, reported separately. B's marginal differences average A0B1/A1B1 versus A0B0/A1B0. B3 additionally reports cancellation request and committed cancellation before the frozen due tick; a blocked request counts as attempted, not completed.
3. **Safety and full-chain readout:** all assigned patched-cell security finding submissions (including inconclusive verdicts), plus validated roots and complete witnesses in vulnerable cells. A-by-B differences and the interaction are exploratory and shown without a confirmatory claim.

The analysis reports each of the four cells of the factorial table, marginal differences, and the difference-in-differences within each stratum. Any intervals use seed-block resampling and are labeled descriptive; no significance threshold or pooled primary effect is declared. Observed-transition-to-report conversion, invalid citation pairs per submit attempt, noncanonical route errors, preflight/catalog use, experiment lifecycle, model calls/tokens, and adjacent response/tool-batch repeats are **mechanistic/descriptive** summaries. Conditioning on a post-assignment transition or submit attempt cannot support a randomized A-effect claim. No preflight output or hidden validator result is shown to the model as an outcome hint.

## Missingness, health, and integrity

Every assigned row remains in every denominator. `score_valid`, `trace_auditable`, `resource_auditable`, and each stage's observability are separate. An intact provider-failed trace can retain preterminal stage observations. A started call with no auditable completion has unknown tokens and cost; unknown is `null`, never zero. Missing stage outcomes receive all-assigned best/worst bounds; no complete-case estimate substitutes for the assigned contrast. An analyzer programming error fails the whole postcheck rather than becoming experimental missingness.

Before each cell, verify the frozen assignment, isolated build, checkpoint receipt, selected endpoint/revision/price, source/protocol/tool hashes, cumulative cost plus the next full-cell ceiling, and absence of a previous run or reservation for that cell. After each cell, reconcile PostgreSQL event sequence and identity, trace and request/evidence hashes, score replay, stage IDs, resource use, and pair receipts. Stop on auth, quota, request, endpoint, price, integrity, reservation, or cap ambiguity. Retain one isolated transport/provider failure without retry after authoritative reconciliation; pause after two consecutive transport failures or three provider failures among ten started cells. Any resumed unstarted suffix or health-epoch reset needs its own reviewed amendment and exact scope-bound human approval. Never settle or replace an outcome-missing call as routine recovery.

The final read-only postcheck must account for **192 assigned outcomes and 96 pair receipts**, all referenced source runs and no extras, every trace/artifact hash, endpoint receipt, and cumulative ledger. It must regenerate the analysis byte-for-byte from a clean pinned protocol checkout. It must report all missing and provider-failed assignments, full stage tables, patched findings, worker-clock positions, and resource uncertainty. Frozen M6.6/M6.6.1 artifacts remain untouched.
